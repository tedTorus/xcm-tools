Fixes #2679

### Description
Astar's chain configuration incorrectly overrode `transferPolkadotXCM` to hardcode the use of the legacy `reserve_transfer_assets` extrinsic. This bypassed the SDK's smart routing logic (which would correctly utilize `transfer_assets_using_type_and_then` with `InitiateTeleport` for teleportable assets like BNC, HDX, and vDOT), causing AssetHub to reject the messages with `UntrustedReserveLocation`.

### Solution
Removed the hardcoded `transferPolkadotXCM` override from `Astar.ts`. Astar now cleanly inherits the default implementation from `SubstrateChain`, allowing it to correctly route teleportable assets via `transfer_assets_using_type_and_then` just like Hydration and Bifrost do.
