Fixes #2678

### Description
When calculating the `paymentInfo` fee for a swap to a destination without dry-run support, `calcPaymentInfoFee` attempts to evaluate the reverse fee using the pre-swap asset. If this asset does not exist on the destination chain, it throws an error (e.g., `TypeAndThenUnavailableError`). Previously, the fallback to evaluate the post-swap asset (`swapConfig.amountOut`) was strictly gated behind `InvalidCurrencyError`, causing other valid failures to be swallowed and returning `0n` as the fee.

### Solution
Broadened the fallback condition to trigger on any error during the pre-swap asset reverse fee calculation, provided a `swapConfig` exists. This ensures the fee is correctly computed using the post-swap asset rather than silently zeroing out.
