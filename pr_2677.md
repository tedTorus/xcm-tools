Fixes #2677

### Description
After a swap operation, `getXcmFee` was incorrectly reporting the destination asset with the pre-swap input amount (`asset.amount`), completely ignoring the post-swap `swapConfig.amountOut`. This resulted in drastically inflated destination amounts being reported.

### Solution
Updated the `currentAsset` assignments in `processHop` and the destination fallback branch to correctly use `swapConfig.amountOut` if the exchange has passed (or if a swap is configured at the destination). This ensures the ED checks and final fee results reflect the actual received asset amount.
